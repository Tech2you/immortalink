Heiro family feed paging — 2026-11-04

Scope
- User approved expanding the newest-memory feed carefully, with fast loading
  and preserved access controls. This task implements 30 newest shared memories,
  ten at a time, within the existing 30-day window. Vault contents are untouched.
- No database migration, Edge Function deployment, dependency upgrade, purchase
  configuration change, TestFlight upload or App Store draft edit was performed.
- Existing uncommitted media, AI and other work was preserved.

Changes
- The feed constructs posts near the viewport instead of constructing every
  loaded post at once. Photo requests begin when those posts are built; existing
  adjacent-photo prefetching and authenticated photo revalidation are retained.
- Initial metadata is limited to ten results plus one lookahead per vault batch.
  Scrolling requests the next ten, with a manual fallback and a ceiling of 30.
- Date filtering runs in the query. Ordering uses creation time and UUID, with a
  stable snapshot upper bound and cursor to avoid offset duplicates during edits.
- Large-family vault batches have at most three memory requests in flight.
  Avatar signing is limited to authors in the requested page.
- Duplicate continuation requests are suppressed. Refreshes supersede pending
  continuation results. Same-family full refreshes coalesce; membership-change
  refresh intent survives intervening media events in the debounce interval.
- Transient continuation failures keep existing posts and offer explicit retry.
  Authorization denials clear content. Cache invalidation and account/family
  guards reject late responses. Membership and hidden-vault scope are rechecked
  on every page. Existing own-vault and About exclusions remain.
- No privileged server credential or public media bucket was introduced. The
  cursor is validated before entering a filter expression; it grants no access.
  Client page limits are performance controls, not a replacement for server RLS.
