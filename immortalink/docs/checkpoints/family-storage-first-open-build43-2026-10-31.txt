Heiro Family storage first-open fix — build 43 — 31 October 2026

Request
Fix the incorrect "Join or create a family" page and repeated reopening/refreshing while preserving the now-working Apple restore and contribution-move flows. Local phone delivery only; no TestFlight upload or App Store draft change.

Cause
VaultsScreen._showSubscriptionSettings captured _activeFamilyId once. If the home screen was still loading its profile/membership/media, the new route received an empty ID and never recovered when that home-screen selection later arrived. Empty/unresolved state was rendered as confirmed missing membership.

Change
The subscription entry point now performs a small authenticated, read-only membership lookup independently of home/profile/media loading. A selected family is retained only if it is still a membership; otherwise the primary/first membership is used. Sign-out/account change and malformed responses are rejected, not treated as an empty family.

FamilyPlanStatusContent shows the existing brand loading artwork while resolving membership, then initializes the existing billing service with the resolved family. One bounded automatic retry follows a brief failure. Persistent failure shows a retryable connection error; only a successful empty lookup shows the join/create message. Confirmed no-family state offers Check again. Resume/periodic refresh can retry unresolved membership. Disposed widgets and superseded lookups cannot initialize billing with old results.

Scope protected
No billing rules, purchase verification, StoreKit handlers, contribution moves, prices, storage allocations, family membership writes, media, relationship code, or live database changes. No purchases, restores or moves were initiated on the user's behalf. Existing unrelated working-tree changes were preserved.
